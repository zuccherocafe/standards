dandegate: group the steps file by project, reports and steps

dandegate.toml mixed what a project is, how the built-in reports are tuned and the steps a project adds in one flat set of tables. It now has three groups: [project] holds host and one table per language ([project.rust] with workspace, [project.godot] with project and tests); [reports] holds [reports.measures] (code, exclude, code-measures) and [reports.rust] (scans, mutation); [steps] holds [steps.inputs] and each [[steps.step]] with its [steps.step.identity]. Every step option keeps its meaning. A later report adds a [reports.<name>] table or a language a [project.<language>] table without changing the format.

This is a clean break: the reader accepts only the new layout, and the old top-level tables are refused as unknown fields. Standards' own dandegate.toml and the documents that describe the file move with it.

The Rust reports now run only when [project.rust] names the workspace; a language with no table is not reported on. Discovering the one Cargo workspace, and the refusal when there were several, are gone, so a Rust project without the table loses its reports until it adds one. When the after revision holds a Cargo workspace but the file has no [project.rust], the page shows and dandegate prints a DANDEGATE-NOTICE line naming the table to add; it does not make the report incomplete. [reports.rust] without [project.rust] is refused, since it would tune nothing; an empty [reports.rust] is the same as none.

Every repository path is relative and plain, a folder written with a trailing / and a file without one, read once into RepoDir, RepoFile or RepoPath and checked against the after revision's tree. The workspace, the Godot project and its tests must be folders the after revision holds, and the workspace must hold a Cargo workspace. [reports.measures] code and exclude may name a path the after revision lacks, since a change can remove measuring code, but a path it holds must be written as what it is. A step's images folder under {out}/ ends in / too. Command words and input defaults are not paths and are not checked.

Every command and kept result's identity is the same as before: a folder is kept without its trailing /. A repository path is a literal name, so the one place one reaches git as a pathspec, Repository::changed (the measuring-code warning and whether any Rust differs), now runs git with --literal-pathspecs. Before, a measuring-code entry such as check[1].sh was a pattern that also matched check1.sh. The --with selection is now checked after the whole file, so every refusal of the file comes before the command line's.
